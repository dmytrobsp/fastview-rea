names stay. The reporter's issues #1–#3 stay open until the milestone merges; they are not closed or commented on
without the maintainer.

**Batching**: all four first units at once (separate code: docking / views, scaling setup, the record dialog and
formulas, the COMTRADE reader). #10 and #13 both touch `recdlg.rs` / `app.rs` in parts apart, checked by merging both
together. #12 builds on #11 and waits for it. At most three clones at once.

**The maintainer's decisions** (2026-10-30):

- Ours may do better than the original where the improvement is obvious, each documented with a clear reason
  ([IMPROVEMENTS.md](../IMPROVEMENTS.md)). For #7: formulas made before a «Кодировка» switch keep working (the
  original fails on them). For #8: the UTF-8 `.cfg` read as UTF-8, U+FFFD kept in cut names, ADC codes beyond ±2³¹
  kept whole — all three approved.
- Pull requests go into a milestone branch; a final review merges it into `main` with the maintainer.
- Implementers no longer push, open pull requests or file issues: the controller does, after its checks. A unit is
  reported done only when nothing known is left; questions come back to the controller and the implementer goes on;
  follow-ups become issues.
- Tracking moves to GitHub Issues; the docs move under `docs/` (this file's folder, [docs/original/](../original/README.md),
  [PROGRESS.md](../PROGRESS.md)).
