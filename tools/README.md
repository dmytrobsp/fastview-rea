# Reverse-engineering tools

Everything here is our own code. None of it ships any part of the original
program: you supply your own copy of the Fast View 5 installer, and the
scripts regenerate the analysis inputs locally. The findings drawn from them
are written up in our own words in [`../docs/original/`](../docs/original/README.md): the
reconstruction record (item by item with the original's addresses) and the
behavioural specs in `specs/` (UI behaviour, views, ОМП, file formats,
computed channels).
Any address cited there can be checked against your own copy.

## 1. Get the original program

The installer `Setup_FastView.exe` (НТЦ «Механотроника», www.mtrele.ru) is a
custom installer with an MSZip cabinet in its PE resources
(`.rsrc/1049/BIN/137`). 7-Zip extracts both layers:

```bash
7z x -oextracted Setup_FastView.exe          # the PE resources
7z x -oextracted/stage1 extracted/.rsrc/1049/BIN/137
```

`extracted/stage1/` then holds `FastView.exe` (MFC 12, MSVC 2013, x86; the
notes cite sha256 `6c503790…d046`, image base `0x400000`), its DLLs, the
help `FastView.chm` and `vcredist_vs13_x86.exe`. `extracted/` is git-ignored.

## 2. Regenerate the dumps

```bash
tools/regen-dumps.sh extracted/stage1/FastView.exe dumps
```

| file | tool | content |
|---|---|---|
| `fv.asm` | `objdump -d -M intel` | the full disassembly the notes' addresses refer to |
| `imports.txt` | `peimports.py` | IAT slot → DLL and function / MFC ordinal |
| `strings.txt` | `pestr.py` | the string table (`id<TAB>text`) |
| `msgmaps.json` | `msgmaps.py` | every MFC message map: class, entries (WM_* / COMMAND / CMDUI, id range, handler address) |
| `vtables.txt` | `vt.py` | RTTI classes, primary vtables, slot counts |

`python3 -I tools/show.py --dumps dumps CFastViewView` prints a class's
message map with command ids resolved to their strings. `dumps/` is
git-ignored.

`python3 -I tools/coverage.py` measures how much of the program's own code
the record in `docs/original/` cites (functions, instructions, the uncited
ones by class). It prints counts and addresses only.

MFC's own resources (e.g. the Russian labels of the print-preview ribbon
category) live in the redistributable: `tools/carve_cabs.py
extracted/stage1/vcredist_vs13_x86.exe vcr/` carves its cabinets, `7z x` them,
then `pestr.py` on `F_CENTRAL_mfc120rus_x86` / `objdump` on
`F_CENTRAL_mfc120u_x86`.

`tools/dlg_templates.py <FastView.exe> [ids…]` prints the dialog templates'
geometry (dialog units, styles, control rectangles), which our dialogs are
laid out from; its output quotes resource text, so it stays local too.

## 3. Decompile

Decompilation was done with [REA](https://www.npmjs.com/package/rea-agents)
(`npx rea-agents mcp`, an MCP server) driving Ghidra 12.1: `open_binary` on
`FastView.exe`, then `procedure_pseudo_code`, `xrefs`, `procedure_callers`,
`read_bytes`, `search_strings`. `ghidra_dump.py` is an older Ghidra headless
post-script that decompiles the formula-engine and `.fvb` parser functions.

## 4. Method

Each behaviour was reversed from the handler that implements it (message map
→ handler → callees), distilled into prose with addresses, implemented in
Rust, pinned by a test, and recorded in the ledger with what was **read**,
what is **inferred** and what is **not determined**. Research questions were
handed to sub-agents with a brief per question (scope, the addresses already
known, the questions, and the rule to report behaviour in prose rather than
code listings).

## 5. Factual indexes and symbols

[`../index/`](../index/) publishes facts about the binary — the message
maps, vtables and imports, and a symbol list naming the functions our notes
describe — regenerated by `index.py` from your copy. `symbols_export.py`
turns the symbol list into a Ghidra, IDA or rizin / radare2 script; see
[`../index/README.md`](../index/README.md).

Other helpers: `pngcrop.py` (crop help screenshots), `msgmaps.py` (used by
`vt.py`, `index.py` and `regen-dumps.sh`).

## Synthetic records

Users' records never go into the repository, so tests need records with the same *structure* and made-up
contents. `python3 -I tools/records/synth_record.py SRC.cfg OUTDIR [--seed N] [--stem NAME] [--rows N]` reads a
record (the `.cfg` and the `.dat` / `.hdr` beside it) as input only and writes a new one with the same COMTRADE
revision and extra lines, text encoding, BOM and line endings, channel counts and kinds (primary / secondary / P-S
fields, digital channels), rate segments (their number and ratios), data type (ASCII with the source's widths and
number styles, BINARY, binary32), analog scaling shape (the exponent of `a`, the range fields, samples spread
over the float32 range), `.hdr` presence and shape, and names cut mid-character (a U+FFFD, or half a UTF-8
sequence at a byte limit) — with every name, text, date, time, rate, time code (its sign and `h` shape kept, the offsets
invented), time-quality / leap-second symbol, factor and sample invented from the seed
(deterministic). It then runs the check below and draws again with the next seed on a clash (up to 50 times). The
source is read at run time; nothing about any source is in the code.

`python3 -I tools/records/userdata_check.py --source SRC.cfg [--source ...] [--max-rows N] OUT.cfg [OUT.cfg ...]` looks
for the source's own values in an output: text fields (names, station, device, dates, times, header lines, the file
name) and words of four letters or more, case-folded; identifying numbers by value (not 0, +-1, whole numbers up to
100, revision years, ADC and float32 ranges) in the `.cfg` / `.hdr` and non-whole data values of six or more digits;
whole `.cfg` / `.hdr` lines; the rate-segment lines and the time-code / quality lines as whole lines, short as they
are (a record's time code is its own value, not structure); phase and ccbm fields by channel position (apart from
format phases such as A, B, C, N, L1); and four-row windows of the analog samples, both of whole rows and of each
channel alone (six consecutive values of one channel, a spread of 16 or more for whole numbers, so that a copied
column shows even at a moderate amplitude while small whole-number samples of unrelated records do not meet by
chance), and, for a timestamp-only record, four consecutive steps of its time column (differences, so an offset does
not hide a copy). It prints counts only, never a value, and exits 1 on any match. It reads at
most `--max-rows` data rows of a record (default 2 000 000) and indexes at most 2 000 000 per-channel windows of it;
the generator's own check after each draw reads at most 200 000 rows of the source.

What the tools keep on purpose, and the check does not compare: the channel-count line and the channel numbers,
digital normal states and the first data row's digital states, format phases, standard units, the P/S flag, the
frequency line, the number of rate segments and the approximate ratios of their rates and sample counts, the layout
of the tokens in names and the punctuation of the `.hdr`, and the data type. A clean check therefore shows that no
value of the source was copied; it does not show that the *structure* is unrecognisable. **A record generated from a
user record stays local** (it is for local runs and for comparing readers); whether such an output may be committed
is the maintainer's decision. Committed fixtures come from hand-written sources, checked against the user records.
Besides a `.cfg` with its `.dat` / `.hdr`, a source may be a **timestamp-only** record (`0` rate segments, one `0,N`
line: the output has the same two lines with an invented count and invented, irregular, increasing instants), a
single-file **`.cff`** (the sections `--- file type: KIND ---` in the source's order, the data section last with its
byte count after a colon or running to the end of the file; every text section, INF and SET too, is invented like a
`.hdr` and checked like one; the BOM, encoding and line endings are kept; the data marker gets the new byte count),
or an OSC2 **`.osc`** (128-byte big-endian blocks; the version, block geometry, tags, channel counts, line layout,
samples per block and number of timing codes are kept, and every name, phase, unit, calibration number, ratio, timing
code, the trigger moment and every sample is invented; bytes the format description does not name are written as
zeros). The check indexes an `.osc`'s names, calibration numbers, ratios, timing codes, trigger moment and sample
windows like the fields of a `.cfg`. Layouts the tools cannot take (a `.cff` without a CFG or DAT section, with text
before its first section or a section after the data; an `.osc` with an unknown text tag, no samples-per-block block,
sample records that do not fit a data block, or channel lines of another shape) are refused with a message.

`tools/records/make_fixtures.py [--check]` rebuilds `crates/fvb-core/tests/data/generated/` from seven hand-written
sources (invented, in the script: a 2013 record with a BOM, a 1999 BINARY one, a cut-name binary32 one, a 1991 one,
a timestamp-only one, a `.cff`, an `.osc`) with fixed seeds; `crates/fvb-core/tests/generated_records.rs` reads them (the fixtures are compiled into the
test executable and written to the temporary directory on first use, so an executable cross-built for Windows runs on a
clone as it is). The tools' tests: `python3 -I -m unittest discover -s tools/records -p 'test_*.py'` (CI runs them).

## The milestone helper

`python3 tools/milestone/milestone.py start|add|gate|ungate|rm|end|ls` does
the git part of running a milestone with several implementers at once: the
milestone branch, a worktree per unit, the merge gate
([`../docs/agents/workflow.md`](../docs/agents/workflow.md#branches-and-worktrees)).
Its tests: `python3 -I -m unittest discover -s tools/milestone -p 'test_*.py'`
(CI runs them).

`tools/review-package.sh BASE HEAD OUT` writes a unit's review package (commits, stat, diff with
context) for an independent reviewer ([`../docs/agents/review.md`](../docs/agents/review.md)).

`tools/watch-report.sh FILE PATTERN MAX_SECONDS [LABEL]` is the controller's watchdog for a dispatched agent: it exits
when FILE gains a line matching PATTERN (READY) or after MAX_SECONDS (TIMEOUT), so the controller is woken even when an
agent's completion notice never arrives ([`../docs/agents/workflow.md`](../docs/agents/workflow.md)).
